# 평가 결과

모든 평가는 MuJoCo 시뮬레이션에서 했다. 실제 로봇은 쓰지 않았고, 사람 입력은 영상 파일을 카메라처럼 실시간 재생해서 넣었다(가짜 카메라).
지표 정의는 [architecture.md](architecture.md) §6.

## 1. 방법

| 방식 | 내용 | 도구 |
|---|---|---|
| 실시간 리허설 | 실제 sender·sim_server(+렌더)를 띄우고 영상 목록을 카메라처럼 순환, 운영자 보행 패턴을 CTRL로 넣음 | `python -m k1live.rehearse` |
| 장시간·장애 시험 | 서비스 전체 + 관객 화면 같은 클라이언트, 정해진 시각에 강제 종료(SIGKILL)·멈춤(SIGSTOP) | `python -m k1live.soak --chaos` |
| GEM-X 라이브 재생 | GEM-X 실시간 프로세스(`gemx_worker.py`)를 영상의 **모든 프레임**에 돌려 덤프(인과적) → 라이브 타이밍(캡처 뒤 34–38 ms 도착)으로 라이브 sender와 같은 매핑에 넣고 → `SimServer.tick()`을 시뮬레이션 시계로 돌림(팔·보행 제한, 방향 유지, 낙상 규칙, 서비스 자동 대기·보정·시작 포함). GPU 속도와 무관하게 같은 결과 | `k1live/gemx_worker.py --dump`, `scripts/gemx_feed.py`, `scripts/eval_hybrid_live.py` |
| 백엔드 비교 | 같은 사람 스트림·같은 명령 경로를 백엔드마다 | `scripts/eval_hybrid.py {walk,stand,switch}`, `scripts/eval_backends.py`, `scripts/eval_presenter.py` |

입력 영상은 Pexels 스톡 영상(제스처·강연자), YouTube Creative Commons 영상, 직접 찍은 영상이며 저장소에 포함하지 않는다. 행사 인식 경로(GEM-X)가 정해진 뒤의
수치는 가능한 한 GEM-X 입력으로 다시 쟀다. 기계: MacBook Pro M2 Max, Ubuntu 24.04 데스크톱(32스레드, NVIDIA 16 GB GPU), 학습 서버(RTX PRO 6000 1장).

## 2. 실시간 루프 (초기 구성: MediaPipe + split)

Mac 3분 리허설(영상 7개 순환, 운영자 보행 123 s):

| 항목 | 결과 | 기준 |
|---|---|---|
| 지연 p50 / p95 / 최대 | 32.1 / 41.9 / 77.3 ms | p95 ≤ 150 ms |
| 제어 주기 평균 / 1 s 창 최소 | 50.0 / 49.96 Hz | 50 ± 2 |
| 실시간 비율 최소 | 0.999 | ≥ 0.98 |
| 정책 추론 p95 | 0.34 ms | ≤ 5 ms |
| 팔 오차(IK 목표 대비) 평균 / p90 | 2.89 / 4.73° | ≤ 8° |
| 손 위치 오차 평균 | 3.95 cm | |
| 낙상 | 0 | 0 |
| 사람이 사라지면 보행 0까지 | 0.14 s | ≤ 0.3 s |

방향 유지(heading hold): 30 s 서서 왼팔 흔들기에서 로봇이 제자리에서 돈 각도 132° → 2°, 0.4 m/s로 걸으며 흔들기 175° → 2°.

## 3. hybrid 백엔드

**걸음 품질** (보행 10종, 라이브와 같은 명령 경로, 정상 걷기 구간 평균, `scripts/eval_hybrid.py walk --server-chain`):

| | split | hybrid (walk3 5000) | **hybrid (walk4 7000, 행사)** |
|---|---|---|---|
| 낙상 / 최대 기울기 | 0/10 / 5.7° | 0/10 / 17.5° | 0/10 / 14.9° |
| 보폭 | 0.146 m | 0.278 m | 0.248 m |
| 걸음 수 | 4.34 /s | 2.36 /s | 2.15 /s |
| 발 들림 | 3.0 cm | 3.0 cm | 4.8 cm |
| 무릎 굽힘 | 45.0° | 30.4° | 30.9° |
| 스탠스 폭 | 0.235 m | 0.268 m | 0.188 m |
| 발 미끄럼 | 0.078 m/s | 0.051 m/s | 0.048 m/s |
| 몸통 기울기 평균 / p95 | 2.4 / 2.9° | 9.5 / 12.1° | 9.0 / 11.2° |
| 속도비 앞 / 뒤 / 옆 / 회전 | 0.90 / 0.73 / 1.12 / 1.57 | 0.72 / 0.98 / 0.61 / 0.99 | 0.75 / 0.96 / 0.77 / 0.99 |

split의 종종걸음(짧은 보폭, 빠른 걸음, 굽은 무릎)이 사라진다. 대가는 걸을 때 몸통이 더 기울고(플래너 참조 자체가 앞으로 숙이고 걷는다) 좌우로 더
흔들리는 것이다. walk4는 walk4 5500–8000 체크포인트 중 발 들림이 가장 크고 스탠스가 가장 좁은 7000을 골랐다.

- **서 있을 때 팔**: STAND는 split과 같은 물리·정책·순서라 비트 단위로 같다(200틱 qpos 차 < 1e-9). 사람 영상 9클립(MediaPipe) PD 팔 경로 0.71° / 1.28°(평균 / p90).
- **전환**: 무작위 걷기/멈춤 + 사람 팔 스트림 6 × 120 s에서 서기↔걷기 전환 402회 낙상 0(행사 설정 265회 포함). 전환 직후 팔 관절 속도 최대 6.8 rad/s(서서
  사람 팔을 따라 할 때 7.5보다 작음).
- **실시간**: 가짜 카메라 + 렌더 + 운영자 보행 4분 — 49.99 Hz, 실시간 비율 1.000, 틱 p95 2.6 ms, 지연 p95 35 ms, 낙상 0.

## 4. GEM-X 입력에서 멈출 때 낙상 → 수정

GEM-X 입력으로 행사 조건 시험을 할 때 약 48분에 낙상 2회가 나왔다. 둘 다 사람이 화면 밖으로 걸어 나가는 순간의 짧은 걷기 뒤 SETTLE(멈추기)였다.

- **원인**: SETTLE이 시작되면 팔이 사람의 '팔 내림' 자세(로봇 손이 엉덩이 안쪽)로 돌아가면서 PD 팔이 손을 엉덩이 링크에 수백 N으로 눌렀고, SONIC 다리가
  균형 걸음을 하지 못했다(재현한 낙상 37회 모두 SETTLE 중 손–엉덩이 접촉).
- **수정**: `settle_arms="walk"` — SETTLE 동안 걷기 팔을 유지하고 다리가 loco로 돌아간 뒤 사람 팔로.

| 시험 (GEM-X 라이브 재생) | 수정 전 | 수정 후 |
|---|---|---|
| 재현 세트(화면 이탈 순간 0.6 s 걷기 의도 주입, 61.7분) | 낙상 16 | **0** (SETTLE 3 s 상한 14 → 0) |
| 다른 주입 세트(합 46.2분) | 낙상 13 | **0** |
| 전환 시험(행사 설정 4 × 120 s / 짧은 걷기 + 팔 급변 8 × 120 s) | 0 / 0 (기울기 22.7°) | 0 / 0 (기울기 15.2°) |
| 서기 팔 정확도 | 0.71° / 1.28° | 같음 |
| 데스크톱 GPU, GEM-X 실시간 12분 | 낙상 1 | **낙상 0**, 지연 p95 95 ms, 제어 중앙 50 Hz |

## 5. 팔 경로 개선 (뼈 방향 IK + PD 팔)

| 입력 / 클립 | 지표 | 기존(위치 IK + mimic 팔, 6 rad/s) | **개선(dir IK + PD 팔, 12 rad/s)** |

| MediaPipe, 상체 13클립 (기준 ViTPose 2D) | IK 목표 2D 오차 평균 / 중앙 | 18.98 / 18.41° | 9.20 / 6.56° |
| | 로봇 2D 팔 오차 평균 / 중앙 | 24.74 / 19.15° | 11.40 / 7.20° |
| | 사람 대비 지연 | 200 ms | 80 ms |
| **GEM-X**, 전신 7클립 (기준 MediaPipe 2D) | 로봇 2D 팔 오차 | 16.25° | **5.3°** |
| | IK 목표 2D 오차 | 14.87° | 4.11° |
| | 사람 대비 지연 | 200 ms | 67 ms |
| **GEM-X**, 제스처 9클립 (허리 위 클립 포함) | 로봇 2D 팔 오차 | 25.28° | 8.21° |
| **GEM-X**, 서기 9클립 (hybrid = split) | 서버 팔 참조 대비 | 2.5° / 1.64 cm | **1.54° / 1.14 cm** (MediaPipe 입력 0.71° / 0.58 cm) |

낙상 0(모든 클립·설정). IK 계산은 프레임당 중앙 1.0–1.8 ms(p95 ≤ 2.1 ms). GEM-X 입력에서 추종 오차가 MediaPipe보다 큰 것은 GEM-X 팔 목표가 프레임 사이에
더 움직이기 때문이다(허리 위만 보이는 클립의 재검출, 깊이 출렁임).

## 6. GEM-X vs MediaPipe — 먼 전신

사람 키가 1080p 화면 높이의 20 / 30 / 45 %가 되게 줄인 17클립(상체 13 + 걷기 4):

| 조건 | MediaPipe(전체 화면) 검출 | MediaPipe + 사람 영역 검출 / 2D 오차 | GEM-X 검출 / 2D 오차 |
|---|---|---|---|
| 원본 | 99.2 % | – | 93.9 % / 5.98° |
| 45 % | 98.5 % | 94.2 % / 10.18° | 94.1 % / 5.82° |
| 30 % | 30.0 % | 94.2 % / 12.73° | 94.0 % / 6.10° |
| 20 % | 2.7 % | 99.7 % / 10.62° | 94.1 % / 6.36° |

(2D 오차 기준 ViTPose 2D. GEM-X 검출 94 %는 창 준비 0.5 s 몫이 빠진 값.) GEM-X는 거리와 상관없이 평평하고, MediaPipe는 사람이 작으면 '사람 찾을 영역'이
있어야 찾는다. 강연자 걷기 5구간(presenter): GEM-X 4/5를 모든 거리에서, MediaPipe + 영역은 4/5 → 2/5 → 1/5. 폐루프(hybrid + walk4 7000) 낙상 0.

자원(데스크톱 GPU, 1080p 30 fps 카메라): GEM-X 프레임당 32 ms, 26 fps, 캡처 → 제어 반영 p50 48 / p95 83 ms(MediaPipe 41 / 43 ms), VRAM 6.2 GB.

## 7. 장시간·장애 시험

**2시간** (초기 통합본: MediaPipe + split, Ubuntu 데스크톱, 리허설 영상 115.6 s 반복, 자동 대기·보정·시작, 장애 8건):

| 항목 | 값 |
|---|---|
| 프로세스 재시작 (sender / sim) | 4 / 4 — 넣은 장애 8건과 같음, 예기치 않은 실패 0 |
| 장애 복구 | 강제 종료 1.4–1.6 s, 멈춤 4.3–4.6 s 안에 정상, 8.4 s 안에 실시간 화면 |
| 지연 p95 (30초 창) 중앙 / 최대 | 43.4 / 52.3 ms |
| 제어 Hz 중앙 / 하위 1 % | 50.0 / 49.96 |
| 낙상 / 리셋 | 0 / 0 |
| 메모리 추세 sender / sim / service | 1.5 / 0.1 / 1.9 MB/h |
| 관객 화면 클라이언트 | 카메라 · 로봇 29.9 fps, 재연결 0 |
| 판정 | 모든 기준 통과([runbook.md](runbook.md) §10) |

**GEM-X 행사 조건** (Ubuntu 데스크톱 GPU, hybrid + walk4 7000, presenter):

| 시험 | 결과 |
|---|---|
| GEM-X 20분, CPU 상한 없음 | 지연 p95 96 ms(최대 103), 제어 중앙 50 Hz · 하위 1 % 47.9, 낙상 0, 재시작 0, 실시간 화면 99.2 % |
| GEM-X 장애 4종 | 1.5–4.8 s에 정상, 실시간까지 9.8–17.2 s(GEM-X 다시 불러오기) |
| 서비스 자체 강제 종료 | 실행기가 다시 띄워 16.1 s에 실시간, 남은 자식 프로세스 정리 |
| GEM-X 프로세스 메모리 | SOMA Warp 커널이 프레임마다 새로 정의되어 3.3 GB/h 늘던 것을 고쳐 31 MB/h |
| CPU만(NVIDIA 미사용) 10분 + 장애 3회 | 지연 p95 44 ms, 50 Hz, 낙상 0, 1.4–4.8 s에 복구. 로봇 화면은 CPU 렌더라 8 fps |
| 네트워크 차단 | 점검·GEM-X 로딩·서비스 3.3분 동안 외부 접속 시도 0건 |

CPU 코어를 12개로 제한한 시험에서는 GEM-X가 몰아 쓰는 순간 상한에 걸려 제어 하위 1 %가 28 Hz까지 떨어졌다. 행사 컴퓨터에서는 상한을 두지 않는다.

## 9. 사람 전신 정책 (BONES-SEED) — 수락 기준 미달

GEM-X 입력, 수락 기준: 낙상 0, 팔 오차 ≤ split, 걷는 사람을 따라 걷기.

| 기준 | split / hybrid | bones 20000 | bones2 25000 (최선) |
|---|---|---|---|
| 낙상 | 0 | 리허설 영상 루프 30분 3, 카메라 쪽으로 걸어오는 사람에서 낙상 | 모든 시험 0. 단 카메라 앞 접근 구간 최대 기울기 44.6°(규칙 45°) |
| 팔 오차 | 2.05° / 1.28° | 17.1° / 19.7° | **13.6°** / 18.0° (7–14배) |
| 걷는 사람 따라 걷기 | – | 옆걸음 발 끌기(발 들림 0 cm) | 옆걸음이 사람 경로에 더 가까움, 발 들림 1.5 cm. 제자리 돌기는 GEM-X가 등 돌린 사람을 놓쳐 못 함 |

판정: 행사 설정에 넣지 않음(hybrid 유지). 체크포인트 사이 편차가 크고(30분 루프 리셋 0–14회), 앞으로 숙임이 리타깃 정의상 약 2.1배로 커지며,
웅크림은 학습 데이터에 없다. 자세한 실험 구성은 [training.md](training.md) §5.

## 10. 화면 녹화 영상으로 한 사전 점검

현장 웹캠 리허설 전에, 예전 데모 앱의 화면 녹화(카메라 부분 640×480, 앱이 좌우 반전·골격선을 그린 상태, 실제 카메라 약 15 fps)를 잘라
카메라 방향으로 되돌려 행사 체인에 넣었다. 사람은 약 3 m에서 팔 동작을 하고, 끝에 카메라 쪽으로 걸어온 뒤 화면 밖으로 나가며 다른 사람이 앞을 지나간다.

| 항목 | 결과 |
|---|---|
| GEM-X 덤프 3회 인식률 | 0.859–0.864 (놓친 구간은 사람이 화면 밖일 때뿐). 지나가는 사람을 따라가지 않음 |
| 라이브 재생 3회 × 8바퀴(596 s) | 낙상 0, 리셋 0, 팔 오차(IK 목표 대비) 1.63–1.71°(p90 3.28–3.48°), 손 2.6–2.7 cm |
| 걷기 | 바퀴마다 1회 — 사람이 카메라 쪽으로 걸어올 때 0.5 s 앞으로(0.21 m/s), 1.8 s 안에 멈춤 |
| 렌더(같은 구간) | GEM-X 팔 오차 2.32° / MediaPipe 4.85°, 둘 다 낙상 0 |
